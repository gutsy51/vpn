# Личный VPN

## Среда и проверки

Основная среда разработки и запуска - Windows cmd. Примеры команд проверяем
в cmd. WSL и Termux используем как дополнительные среды. Для каждой среды
создаём своё окружение через uv. Корневая .venv принадлежит Windows.
В WSL и Termux задаём UV_PROJECT_ENVIRONMENT с путём в файловой системе этой среды.
Зависимости и uv.lock обновляем через uv.

```cmd
uv sync --locked
uv run pytest
uv run ruff check src tests
uv run ruff format --check src tests
uv run pyright
```

## Архитектура

- Группируем код по задачам. CLI и меню разбирают ввод и показывают результат.
  Сценарий получает типизированные аргументы и возвращает данные. Это позволяет
  вызвать одну операцию из меню, команды или теста.
- Telegram и MAX владеют своими обработчиками, клиентами и форматами сообщений.
  Общие команды получают ID отправителя и данные запроса. Права проверяем по ID
  пользователя. Чат для уведомлений задаём отдельно.
- Для Linux-узлов используем общий SSH и операции с сервисами. Интеграции с API хостинга добавляем отдельно. Первые проверки выполняем на тестовом контуре.
- Перед добавлением класса ищем существующий сценарий. Вводим общий интерфейс,
  когда у вызывающего кода есть конкретная потребность подменять реализацию.
  Для типовых задач выбираем библиотеку, если она упрощает реализацию.
- Общие настройки храним в локальном .env. Имена используемых параметров
  и примеры без секретов указываем в .env.example. Боевые действия выполняем
  по явному запросу. Проверки разрабатываем на тестовом контуре.

## Стиль

- Общаемся и пишем сообщения, комментарии, docstring и документацию по-русски.
  Идентификаторы, имена файлов, CLI-команды и ключи конфигурации пишем по-английски.
- Используем обычный дефис и прямые кавычки. Опускаем эмодзи, декоративные
  разделители, типографские тире и кавычки. Пишем, что делает команда, какие
  данные ей нужны и какой результат она возвращает.
- Используем понятные имена и типы. Комментарии оставляем для решений, причину
  которых нельзя понять по коду.
- Отделяем смысловые блоки пустыми строками. Ставим пустые строки вокруг
  многострочных управляющих блоков и отделяем return от соседних инструкций.
