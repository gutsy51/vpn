## Запуск из Windows CMD

Из корня проекта выполните:

```cmd
uv sync --locked
uv run vpn-manager config check
uv run vpn-manager
```

Команда config check проверяет локальные настройки в .env. Перечислите имена
узлов в VPN_NODES через запятую. Для каждого имени задайте параметры с его
префиксом в верхнем регистре, например FORNEX_SSH_HOST, FORNEX_SSH_USER,
FORNEX_SSH_PASSWORD и FORNEX_SERVICES. Службы перечисляются через запятую.
SSH_PORT по умолчанию равен 22. SSH_KNOWN_HOSTS позволяет указать свой файл
проверенных ключей. Образец находится в .env.example.

При открытии консоли автоматически загружается сводка всех служб. Статусы появляются
по мере ответа узлов. Каждая строка содержит время последней проверки. Подключение
по SSH ограничено пятью секундами, вся операция - двадцатью.

| Клавиша | Действие |
|---|---|
| 1 | Открыть сводку сохранённых в этом сеансе результатов |
| 2 или Enter в списке | Запросить состояние выбранной службы |
| 3 | Открыть последние 100 строк журнала |
| 4 | Обновить все статусы |
| 5 | Добавить сервер и сохранить его настройки в текущий файл окружения |
| 0 | Выйти |
| Tab, стрелки | Перейти между панелями, выбрать службу или прокрутить журнал |

В форме добавления укажите имя, адрес SSH, порт, пользователя, пароль и службы.
Tab переключает поля и кнопки, Escape отменяет ввод. Кнопка "Сохранить" добавляет
сервер в сводку и запускает проверку. Ctrl+P открывает палитру тем.

Для скриптов доступны команды:

```cmd
uv run vpn-manager nodes
uv run vpn-manager check AdminVPS x-ui
uv run vpn-manager logs AdminVPS x-ui
```

## Telegram

Укажите в .env токен от BotFather в TELEGRAM_BOT_TOKEN. В TELEGRAM_ADMIN_IDS
и TELEGRAM_USER_IDS перечислите числовые ID через запятую. Запустите менеджер:

```cmd
uv run vpn-manager serve
```

Для подключения бота через локальный прокси v2rayN добавьте в `.env`:

```dotenv
TELEGRAM_PROXY_ENABLED=1
TELEGRAM_PROXY_URL=http://127.0.0.1:10808
```

Укажите фактический адрес и порт прокси. Значение `0` включает прямое
подключение. После изменения настроек перезапустите менеджер.

В личном чате отправьте /start или /status и выберите узел и службу.
При запуске менеджер параллельно принимает обновления Telegram и запрашивает
состояния служб. Наблюдатель видит последний
результат и время проверки. Администратору доступны свежая проверка и последние
строки журнала. Результаты хранятся в памяти до остановки процесса.

В полноэкранной консоли нажмите **6 - Боты**, чтобы открыть журнал Telegram.
Экран показывает последние 100 строк и обновляется каждые две секунды.
В журнале Telegram и журнале службы Ctrl+C, F8 и правая кнопка мыши копируют
выделенный текст или весь журнал, если выделения нет.
Клавиша 4 обновляет журнал сразу, 0 или Esc возвращает к серверам.
Процесс serve пишет события в .local/logs/telegram.log рядом с используемым .env.
Для просмотра укажите тот же --env-file, что и при запуске менеджера.

В разделе **6 - Боты** показано состояние процесса менеджера. Здесь **1** запускает
`serve` в фоне с текущим файлом окружения, **2** останавливает его, **3** перезапускает.
Закрытие консоли оставляет менеджер работающим. Управление доступно также для
экземпляра, запущенного командой `vpn-manager serve` с тем же файлом окружения.

## Синхронизация с AdminVPS

В Bash Ubuntu используйте алиас:

```bash
vpn-syncbl
```

Алиас определён в `~/.bash_aliases` и подключается по SSH к `adminvps2`.
Он синхронизирует локальное рабочее дерево с Git-репозиторием
`/opt/vpn-manager`, выполняет `uv sync --locked --no-dev`, перезапускает
`vpn-manager.service` и открывает журнал. На сервер попадают и локальные
незакоммиченные изменения. Синхронизация использует отдельный индекс и
не меняет локальную ветку или индекс Git.

Алиас обновляет установленную службу. На AdminVPS уже должны быть настроены
`uv`, пользователь `vpn-manager` и `/var/lib/vpn-manager/.env`.
Для изменений токена или прокси обновите серверный `.env` и перезапустите
службу.

Запуск и управление установленным менеджером из CMD:

```cmd
uv run --locked vpn-manager start
uv run --locked vpn-manager attach
```

`start` запускает `vpn-manager.service` на AdminVPS. `attach` по SSH открывает
экран **Боты / Менеджер** с состоянием службы, журналом и кнопками управления.
В этом экране **F12** останавливает менеджер вместе с Telegram-ботом.
Службы VPN продолжают работать. Для повторного запуска используйте `start`.
Выход из интерфейса оставляет службу работать. Команда `serve` запускает
локальный процесс в текущем терминале.
