# Мониторинг и боты

## Проверки

| Тип | Что проверяет |
| --- | --- |
| `tcp` | Соединение с адресом и портом. С `proxy_port` соединение устанавливает локальный SOCKS5 |
| `https` | TLS и ожидаемый HTTP-статус из сети наблюдателя |
| `tunnel` | HTTPS через SOCKS5 на `127.0.0.1`. Имя разрешается на стороне прокси |

На каждый VPN-туннель нужен свой локальный SOCKS5-клиент и отдельный профиль VPN.
В рабочую конфигурацию добавьте проверку в обычном маршруте и проверку через туннель.
После трёх последовательных сбоев по умолчанию создаётся алерт. Telegram и MAX
имеют отдельные очереди. При сбое API сервис повторит доставку в следующем цикле.

~~~bash
cp ops/monitor.example.toml ops/monitor.local.toml
uv run vpn-manager monitor run --config ops/monitor.local.toml --dry-run
uv run vpn-manager monitor status
~~~

## Два VPS, домашняя сеть и LTE

Да, два VPS могут проверять друг друга. На AdminVPS задайте `probe = "adminvps"`
и адрес второго VPS. На втором задайте другое имя точки и адрес AdminVPS.
Обычная проверка показывает, например, что AdminVPS может достучаться до второго
VPS. Чтобы проверить путь из России, добавьте второй тест через собственный
выход в нужной сети:

~~~bash
ssh -NT -o ExitOnForwardFailure=yes -D 127.0.0.1:1081 ru-probe
~~~

~~~toml
[[checks]]
name = "peer-from-ru"
kind = "tcp"
host = "vpn-reserve.example.com"
port = 443
proxy_port = 1081
~~~

`ru-probe` - SSH-алиас вашей машины, из которой нужно измерить маршрут. У неё
должен работать выход в интернет через выбранного провайдера. TCP-соединение
к VPN-узлу устанавливает эта машина: маршрут от неё может проходить через
фильтры её оператора. Российский VPS, домашний интернет и мобильная SIM дадут
разные результаты. Для проверки белых списков нужен узел с SIM интересующего
оператора и проверка в момент ограничений. Домашний мини-ПК с LTE-модемом
подходит для этого лучше, чем наблюдатель в случайном российском дата-центре.
Доступность TCP-порта не доказывает, что проходит весь VPN-трафик. Для этого
нужно выполнить HTTPS через тестовый VPN-клиент с той же точки.

При одновременном падении обоих VPS взаимные алерты не помогут. Укажите
отдельный `VPN_MANAGER_HEARTBEAT_URL` на каждом VPS. Внешний проверщик сможет
сообщить о пропущенных циклах. Для Telegram опрос включайте на одном узле
на один токен. На втором можно оставить только алерты. MAX webhook тоже
направляйте на одну точку. [Исследование ТСПУ](https://ensa.fi/papers/tspu-imc22.pdf)

## Чаты и роли

В личном чате или группе, где бот получает команды и может отвечать:

- `/status` показывает последние статусы публичных проверок.
- `/checks` перечисляет настроенные проверки, доступные отправителю.
- `/check adminvps-tcp` проверяет соединение с портом сервера. Для проверки панели
  добавьте именованную HTTPS-проверку в TOML и укажите ожидаемый HTTP-статус.
- `/ping <имя>` вызывает ту же проверку. Результат кешируется на 30 секунд.
- Администратор может запускать приватные проверки. Ответ приходит в чат команды.
- `/whoami` показывает ID отправителя и его роль.
- `/diagnostics` для администратора показывает время проб и очередь доставки.

Отметьте проверки, которые можно показывать в чатах, через `public = true`.
Список администраторов задайте в `.env` через `TELEGRAM_ADMIN_IDS` и
`MAX_ADMIN_IDS`. Это ID пользователей, по одному списку на платформу, значения
через запятую. `*_CHAT_ID` задаёт получателя рассылки алертов. Для ответов на
команды этот ID не требуется. Доступ к Docker и кабинетам провайдеров идёт
через локальную консоль.

Для Telegram укажите `TELEGRAM_BOT_TOKEN` и `TELEGRAM_POLL_UPDATES=1`.
Добавьте бота в группу и используйте `/status@имя_бота`, если настройки
приватности Telegram требуют явного обращения. [Telegram Bot API](https://core.telegram.org/bots/api#getupdates)

Для MAX укажите `MAX_BOT_TOKEN`, `MAX_WEBHOOK_PORT=8765` и случайный
`MAX_WEBHOOK_SECRET`. Секрет можно получить через `openssl rand -hex 32`.
Сервис слушает `127.0.0.1:8765`. На HTTPS-входе настройте передачу
`/max/webhook` в этот порт и оставьте заголовок `X-Max-Bot-Api-Secret`.
Сертификат публичного домена должен пройти проверку MAX. Если порт 443 уже
занят Xray, разместите webhook на отдельном HTTPS-входе с доступом к
сервису. После запуска зарегистрируйте адрес командой:

~~~bash
uv run vpn-manager bot max-subscribe https://bot.example.com/max/webhook
~~~

Для исходящих запросов к MAX при необходимости задайте `MAX_CA_FILE` с
официальным PEM Минцифры. Доверие применяется только к MAX.
[Документация MAX](https://dev.max.ru/docs-api/methods/POST/subscriptions/)

## Сервис Ubuntu

Сначала подготовьте локальную конфигурацию и проверьте её вручную:

~~~bash
uv sync --locked --no-dev --python /usr/bin/python3
uv run --locked --no-dev vpn-manager monitor run \
  --config ops/monitor.local.toml --dry-run
~~~

В примере репозиторий размещён в `/opt/vpn`. Каталог и `.venv` должны быть
доступны на чтение пользователю `vpn-manager`. Для этого сервиса используйте
системный Python: служба не читает домашние каталоги.

~~~bash
getent passwd vpn-manager >/dev/null || \
  sudo useradd --system --user-group --no-create-home vpn-manager
sudo install -d -m 0755 /etc/vpn-manager
sudo install -m 0644 ops/monitor.local.toml /etc/vpn-manager/monitor.toml
sudo install -m 0640 -o root -g vpn-manager .env /etc/vpn-manager/.env
sudo install -m 0644 ops/systemd/vpn-manager.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now vpn-manager.service
~~~

Подготовьте `.env` по [.env.example](../.env.example) и
оставьте только параметры мониторинга и ботов. Сертификаты указывайте абсолютным
путём и разрешите сервису читать эти файлы. Сервис пишет состояние в
`/var/lib/vpn-manager/state.sqlite3`. Для паузы выполните
`sudo systemctl stop vpn-manager.service`.

## Журналы сервисов

Из корня проекта выполните `uv run vpn-manager logs xray` для локального Docker Compose
или `uv run vpn-manager logs x-ui` для журнала systemd на AdminVPS. Команда читает
последние 100 строк. Для x-ui нужен SSH-алиас adminvps с правом читать журнал.

В личном чате Telegram или MAX администратору доступны `/logs xray` и `/logs x-ui`.
Бот возвращает последние 1900 символов. Команда `/logs` показывает имена сервисов.
